# 大鱼AI编程助手

大鱼AI编程助手是一个 IntelliJ IDEA 插件，用来把“在 IDE 中准备上下文、到 AI 中生成方案、再把 AI 返回的代码变更应用回项目”这套流程半自动化。

当前插件不直接调用 AI API。它的定位是：在 IDEA 中快速收集代码上下文并生成规范提示词，用户把提示词复制到自己使用的 AI 工具中，拿到结构化 JSON 响应后再粘回插件，由插件解析、预览并应用代码变更。

## 功能概览

- 在编辑器中选中代码后，一键加入 AI 上下文。
- 在项目视图中选择文件或目录，一键追加文件内容。
- 支持“紧凑模式”收集文件结构和关键签名，减少上下文体积。
- 自动生成约束清晰的提示词，要求 AI 返回可解析的 JSON。
- 解析 AI 返回的 `CREATE`、`OVERWRITE`、`UPDATE`、`INSERT_AFTER`、`DELETE` 操作。
- 在右侧工具窗口预览变更、查看 AI 思路与反馈、加载 AI 要求补充的文件上下文。
- 支持单项变更、文件级变更和全部变更应用。
- 变更应用后保存请求和响应历史，便于回看和复用。

## 环境要求

- IntelliJ IDEA 2024.3 及以上版本。
- 项目构建和打包需要 JDK 17+。
- 本仓库使用 Gradle Wrapper 构建。

开发运行时，`build.gradle` 中的 `intellijPlatform.local(...)` 需要指向本机 IntelliJ IDEA 安装目录。如果路径不一致，请先改成自己的 IDEA 路径。

## 安装方式

### 方式一：从本地 ZIP 安装

1. 在仓库根目录执行构建：

   ```bash
   ./gradlew build
   ```

   Windows 可以执行：

   ```bat
   gradlew.bat build
   ```

2. 构建完成后，在 `build/distributions/` 下找到插件 ZIP 包。

3. 打开 IntelliJ IDEA。

4. 进入 `Settings` / `Preferences` -> `Plugins`。

5. 点击齿轮按钮，选择 `Install Plugin from Disk...`。

6. 选择上一步生成的 ZIP 包并安装。

7. 重启 IDEA。

8. 打开项目后，在右侧工具窗口栏中找到“大鱼AI编程助手”。

### 方式二：开发调试运行

在仓库根目录执行：

```bash
./gradlew runIde
```

Windows：

```bat
gradlew.bat runIde
```

该命令会启动一个带插件的沙箱 IDEA，用于本地开发和调试。

## 首次使用

打开任意项目后，插件会在项目根目录下自动维护 `.ai-assistant/` 目录。该目录用于保存配置和历史记录。

默认配置文件为：

```text
.ai-assistant/config.json
```

配置文件用于控制“添加文件/目录到上下文”时的忽略规则，以及生成完整提示词时的角色和作者信息。默认会忽略 `.git/`、`.idea/`、`build/`、`target/`、`node_modules/`、`*.class`、`*.jar` 等内容。

示例：

```json
{
  "ignore": [
    ".git/",
    ".idea/",
    "build/",
    "target/",
    "node_modules/",
    "*.class",
    "*.jar"
  ],
  "promptExpertRole": "JAVA专家",
  "authorName": "yuqf"
}
```

其中 `promptExpertRole` 会用于提示词开头的“你是一位资深的 ...”，`authorName` 会用于“新创建的文件需标注 `@author ...`”。修改配置后，点击工具窗口中的“刷新配置”按钮，让新的配置立即生效。

## 基本使用流程

### 1. 收集上下文

你可以用三种方式把上下文加入插件输入区。

#### 选中代码片段

1. 在编辑器中选中一段代码。
2. 右键选择“添加到大鱼AI编程助手”。
3. 插件会把代码内容、文件路径、行号和语言类型写入左侧输入区。

快捷键：

```text
Ctrl + Shift + A
```

#### 添加文件或目录

1. 在 Project 视图中选中文件或目录。
2. 右键选择“添加到大鱼AI编程助手”。
3. 插件会递归读取可处理的文本文件，并按 `.ai-assistant/config.json` 的忽略规则过滤不需要的内容。

#### 使用紧凑模式

1. 在 Project 视图中选中文件或目录。
2. 右键选择“添加到大鱼AI编程助手（紧凑）”。
3. 插件会尽量只保留结构、签名和关键内容，适合在上下文较大时使用。

### 2. 补充你的需求

在左侧输入区的“我的需求”部分写清楚目标，例如：

```text
请帮我修复这个解析逻辑。要求：
1. 保留现有公开方法签名；
2. 不做无关格式化；
3. 如果信息不足，请在 requires 中列出需要补充的文件。
```

如果需要区分多个任务，可以在工具栏右侧的“主题”输入框中写一个名称。应用变更后，历史记录目录会使用这个主题名。

### 3. 生成提示词并复制

1. 点击工具窗口中的“生成提示词”。
2. 插件会把当前输入区内容包装成完整提示词。
3. 点击“复制”，把提示词复制到剪贴板。

### 4. 到 AI 工具中生成方案

把提示词粘贴到你常用的 AI 工具中，例如 ChatGPT、Claude、通义千问、DeepSeek 等。

当涉及代码修改时，提示词会要求 AI 返回 JSON，并放在 `json` 代码块中。插件能解析的核心结构如下：

```json
{
  "thought": "实现思路",
  "feedback": "补充说明或注意事项",
  "commands": ["可选命令"],
  "actions": [
    {
      "action": "UPDATE",
      "filePath": "src/main/java/example/Demo.java",
      "oldCodeBlock": "原始代码片段",
      "newCodeBlock": "修改后的代码片段",
      "explanation": "修改原因"
    }
  ],
  "requires": {
    "files": ["需要补充的文件路径"],
    "classes": ["需要补充的类名"]
  }
}
```

支持的 `action` 类型：

- `CREATE`：创建新文件。
- `OVERWRITE`：覆盖整个文件。
- `UPDATE`：替换目标文件中的一段已有代码。
- `INSERT_AFTER`：在目标代码片段之后插入新内容。
- `DELETE`：删除目标代码片段或文件。

## 解析和应用变更

### 1. 粘贴 AI 响应

1. 复制 AI 返回的完整内容。
2. 回到 IDEA 的“大鱼AI编程助手”工具窗口。
3. 点击“粘贴”，或手动粘贴到右侧输出区。

### 2. 解析响应

点击“解析”。

解析成功后，右侧会切换为变更预览视图：

- “思路与反馈”区域显示 AI 返回的 `thought`、`feedback` 和 `commands`。
- “变更摘要”按文件展示待应用的变更。
- “所需补充”展示 AI 在 `requires` 中要求补充的文件或类。

如果 AI 返回的是普通 Markdown 文本而不是结构化 JSON，插件会把它作为反馈展示，不会生成可应用变更。

### 3. 补充上下文

如果预览中出现“所需补充”：

- 双击某个文件或类，插件会尝试把对应内容加载到输入区。
- 也可以右键选择“加载到工作区”或复制路径后手动处理。
- 补充上下文后，再次生成提示词并让 AI 继续输出完整方案。

### 4. 查看差异

在变更树中：

- 双击文件节点，可以查看该文件的所有变更对比。
- 双击单个变更节点，可以查看该变更的新旧内容对比。
- 右键单个变更，可以选择“新旧对比”“应用此变更”“复制新内容”“复制目标内容”“删除”。

建议先查看差异，再应用变更。

### 5. 应用变更

你可以按不同粒度应用：

- 右键单个变更，选择“应用此变更”。
- 右键文件节点，选择“应用全部变更”，应用该文件下的所有变更。
- 右键根节点，选择“应用全部变更”，应用本次响应中的全部变更。

应用后，插件会：

1. 根据 `filePath` 定位项目文件。
2. 根据 `oldCodeBlock` 匹配目标代码。
3. 写入 `newCodeBlock` 或 `content`。
4. 对相关文件执行格式化。
5. 通过 IDEA 的写命令执行变更，因此可以使用 IDEA 的撤销能力回退。
6. 保存本次请求和响应历史。

## 历史记录

历史记录保存在：

```text
.ai-assistant/history/
```

每次应用变更后，插件会按时间和主题创建目录：

```text
.ai-assistant/history/
└── 2026-05-22_10-30-00_默认主题/
    ├── request.md
    └── response.json
```

在工具窗口中切换到“历史记录”页，双击某条历史，可以把当时的请求和响应重新加载回工作区。

## 推荐工作方式

### 小改动

1. 选中相关方法或类。
2. 添加到大鱼AI编程助手。
3. 写清楚需求。
4. 生成提示词并复制给 AI。
5. 粘回 JSON 响应。
6. 解析、查看差异、应用。

### 多文件改动

1. 先添加入口类、核心服务、相关模型。
2. 必要时添加项目目录结构。
3. 让 AI 先分析是否缺上下文。
4. 如果 AI 返回 `requires`，按提示补充文件。
5. 再让 AI 输出最终 JSON 变更。
6. 按文件逐个预览并应用。

### 上下文很大时

1. 优先使用“添加到大鱼AI编程助手（紧凑）”。
2. 在需求中明确说明只需要修改哪些模块。
3. 让 AI 通过 `requires` 请求缺失文件，而不是一次性塞入整个项目。

## 注意事项

- `oldCodeBlock` 必须尽量来自真实文件内容，并且在目标文件中唯一，否则插件可能无法定位或拒绝应用。
- AI 如果返回了重复内容，尤其是 `INSERT_AFTER` 把旧代码也包含进 `newCodeBlock`，可能导致重复插入。生成提示词中已经约束 AI 避免这种情况，但应用前仍建议检查差异。
- 应用大范围变更前，建议先确认 Git 工作区状态，确保可以随时回滚。
- `.ai-assistant/` 是项目运行数据目录，是否提交到版本库取决于团队约定。通常历史记录不建议提交。
- 当前插件主要处理文本文件和常见代码文件，不适合加入大型二进制文件。

## 常见问题

### 构建时报 Java 版本过低

本项目需要 JDK 17+。如果 Gradle 使用了 Java 8，请先设置 `JAVA_HOME` 到 JDK 17 或更高版本。

### 解析后没有变更预览

通常是 AI 没有返回符合格式的 JSON。请确认返回内容中包含 `actions` 数组，并且 JSON 放在 `json` 代码块中。

### 应用变更失败

常见原因：

- `filePath` 不正确。
- `oldCodeBlock` 与当前文件内容不一致。
- 同一段 `oldCodeBlock` 在文件中出现多次，无法唯一定位。
- 目标文件不存在且操作类型不是 `CREATE` 或 `OVERWRITE`。

可以把目标文件重新添加到上下文，让 AI 基于最新内容重新生成变更。

### 添加目录时上下文太大

检查 `.ai-assistant/config.json` 的忽略规则，排除 `build/`、`target/`、`node_modules/`、日志、生成代码等目录。也可以改用“紧凑模式”。
